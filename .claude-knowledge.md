## Erro 1: TypeScript - Parâmetros string | undefined em funções que esperam string

**Erro Identificado:**
```
Argument of type 'string | undefined' is not assignable to parameter of type 'string'.
Type 'undefined' is not assignable to type 'string'.
```
Arquivo: `app/utils/signatureTemplates.ts` linhas 108-111, 154-157, 186-188

**Soluções Tentadas (Inúteis):**
- Criar função `safeSocialIcon` que verifica se url existe - **FALHOU** porque o problema era o parâmetro `color`, não `url`
- Tentar usar operador ternário `url ? socialIcon(...) : ""` - **FALHOU** pelo mesmo motivo

**Causa Raiz:**
Os campos `primaryColor` e `secondaryColor` na interface `SignatureData` são opcionais (`string | undefined`), mas as funções de renderização passam esses valores diretamente para `safeSocialIcon` que espera `string`.

**Solução Adotada:**
Adicionar valores padrão no `DEFAULT_SIGNATURE` em `app/types/signature.ts`:
```typescript
primaryColor: "#1f2937",
secondaryColor: "#6b7280",
template: "modern", // Adicionado também
```

## Erro 2: tsconfig.json - ignoreDeprecations valor inválido

**Erro Identificado:**
```
Invalid value for '--ignoreDeprecations'.
FILE tsconfig.json:12:27
```

**Soluções Tentadas (Inúteis):**
- Usar valor string `"6.0"` - **FALHOU** porque TypeScript espera array

**Causa Raiz:**
A opção `ignoreDeprecations` no TypeScript 5.x espera um array de strings, não uma string única.

**Solução Adotada:**
Alterar de string para array:
```json
"ignoreDeprecations": ["6.0"],
```

## Erro 3: useToast não disponível em #imports

**Erro Identificado:**
```
[unimport] failed to find "useToast" imported from "#imports"
```
Arquivos: `app/pages/login.vue`, `app/pages/plans.vue`, `app/components/signature/ExportActions.vue`

**Soluções Tentadas (Inúteis):**
- Importar de `#imports` - **FALHOU** porque `useToast` não é um composable nativo do Nuxt
- Tentar usar `@nuxt/ui` - **FALHOU** porque o módulo não está configurado

**Causa Raiz:**
`useToast` é um composable do módulo `@nuxt/ui` que não está instalado/configurado no projeto. O Nuxt não fornece um composable de toast nativo.

**Solução Adotada:**
Criar um composable próprio de toast em `app/composables/useToast.ts`:
```typescript
export const useToast = () => {
  const toasts = ref<Array<{ id: string; message: string; type: 'success' | 'error' | 'info' }>>([])

  function addToast(message: string, type: 'success' | 'error' | 'info' = 'info') {
    const id = Date.now().toString()
    toasts.value.push({ id, message, type })
    setTimeout(() => {
      toasts.value = toasts.value.filter(t => t.id !== id)
    }, 3000)
  }

  return { toasts, success, error, info }
}
```

E atualizar os imports nos arquivos:
- `app/pages/login.vue`: `import { useToast } from "~/composables/useToast"`
- `app/pages/plans.vue`: `import { useToast } from "~/composables/useToast"`
- `app/components/signature/ExportActions.vue`: `import { useToast } from "~/composables/useToast"`

Remover o parâmetro `description` das chamadas de `toast.success()` pois nossa implementação simplificada não suporta.

## Erro 4: Componentes @nuxt/ui não configurados

**Erro Identificado:**
```
WARN ENOENT: no such file or directory, scandir 'components/ui'
```
Vários componentes usam: `UContainer`, `UCard`, `UButton`, `UInput`, `Label`

**Soluções Tentadas (Inúteis):**
- Adicionar `@nuxt/ui` aos módulos - **FALHOU** porque causa conflitos e não resolve o problema de componentes faltantes
- Tentar usar `shadcn-nuxt` - **FALHOU** porque os componentes não foram gerados

**Causa Raiz:**
O projeto está migrando de React para Nuxt e os componentes do @nuxt/ui não foram configurados. O diretório `components/ui` não existe.

**Solução Adotada:**
Converter todos os componentes do @nuxt/ui para elementos HTML estilizados com Tailwind CSS:
- `UContainer` → `div class="container mx-auto"`
- `UCard` → `div class="bg-card rounded-lg shadow border border-border"`
- `UButton` → `button` com classes Tailwind
- `UInput` → `input` com classes Tailwind
- `Label` → `label` com classes Tailwind

**Arquivos Convertidos:**
- `app/pages/index.vue`: UContainer → div com container mx-auto
- `app/pages/login.vue`: UCard, UInput, UButton → div, input, button com Tailwind
- `app/pages/plans.vue`: UCard, UButton → div, button com Tailwind
- `app/components/signature/ExportActions.vue`: UButton → button com Tailwind

**Classes Tailwind Padrão Usadas:**
- Botão primário: `bg-primary text-primary-foreground rounded-md hover:bg-primary/90`
- Botão outline: `border border-input rounded-md bg-background hover:bg-muted`
- Botão ghost: `hover:bg-muted`
- Input: `px-3 py-2 border border-input rounded-md bg-background focus:outline-none focus:ring-2 focus:ring-ring`
- Card: `bg-card rounded-lg shadow border border-border`

## Erro 11: ExportActions component não resolvido

**Erro Identificado:**
```
[Vue warn]: Failed to resolve component: ExportActions
```
Arquivo: `app/pages/index.vue`

**Causa Raiz:**
O componente `ExportActions` está sendo usado mas o Nuxt não está conseguindo encontrá-lo. Isso pode acontecer porque:
- O componente está em `app/components/signature/ExportActions.vue`
- Nuxt 4 com compatibilidade versão 4 usa convenção de nomenclatura diferente
- O componente não está sendo importado explicitamente

**Possíveis Soluções:**
1. Verificar se o arquivo existe em `app/components/signature/ExportActions.vue`
2. Importar explicitamente o componente: `import ExportActions from "~/components/signature/ExportActions.vue"`
3. Usar o nome completo do caminho: `<SignatureExportActions>` ou `<signature-export-actions>`
4. Verificar se há erros de sintaxe no componente que impedem seu carregamento

## Erro 12: Traduções intlify não encontradas

**Erro Identificado:**
```
[intlify] Not found 'home.subtitle' key in 'pt' locale messages.
[intlify] Not found 'form.name' key in 'pt' locale messages.
[intlify] Not found 'form.role' key in 'pt' locale messages.
[intlify] Not found 'form.company' key in 'pt' locale messages.
[intlify] Not found 'form.website' key in 'pt' locale messages.
[intlify] Not found 'form.template' key in 'pt' locale messages.
```

**Causa Raiz:**
O módulo `@nuxtjs/i18n` está configurado mas os arquivos de tradução estão incompletos ou mal formatados. As chaves usadas no código (`home.subtitle`, `form.name`, etc.) não existem no arquivo `pt.json`.

**Possíveis Soluções:**
1. Verificar se o arquivo `app/locales/pt.json` existe e está corretamente formatado
2. Adicionar as chaves faltantes ao arquivo de tradução:
```json
{
  "home": {
    "subtitle": "Subtítulo da página inicial"
  },
  "form": {
    "name": "Nome",
    "role": "Cargo",
    "company": "Empresa",
    "website": "Website",
    "template": "Template"
  }
}
```
3. Alternativamente, desabilitar o `typeCheck` do i18n no `nuxt.config.ts` se as traduções não forem críticas

## Padrões de Evitar Erros

### Antes de usar composable de #imports:
1. Verificar se é um composable nativo do Nuxt (useNuxtApp, useRoute, useRouter, useState, etc.)
2. Se não for nativo, verificar se o módulo correspondente está instalado
3. Se não estiver instalado, instalar o módulo ou criar uma implementação própria

### Antes de usar componentes de UI:
1. Verificar se o componente existe no projeto
2. Se não existir, usar Tailwind CSS puro em vez de depender de bibliotecas externas
3. Manter consistência no estilo usando classes Tailwind

### Antes de modificar arquivos TypeScript:
1. Ler o arquivo atual primeiro (pode ter sido modificado por linter)
2. Verificar se há valores padrão necessários
3. Usar valores padrão em interfaces para evitar `undefined`

### Resolução de componentes no Nuxt 4:
1. Componentes em subdirectórios são auto-importados com caminho relativo ao diretório
   - `app/components/signature/ExportActions.vue` → `<SignatureExportActions>` ou `<signature-export-actions>`
   - Alternativamente, importar explicitamente se o nome auto-gerado não funcionar
2. Verificar se o arquivo existe fisicamente antes de疑
3. Se um componente não é encontrado, tentar import explícito com caminho completo
